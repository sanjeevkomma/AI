# Architectures used to develop a Language Model
1. N-gram Models
2. Recurrent Neural Networks (RNNs)
3. Long Short-Term Memory (LSTM)
4. Gated Recurrent Units (GRUs)
5. Transformer Architecture
6. Auto-Regressive Models (e.g., GPT)
7. Auto-Encoding Models (e.g., BERT)
8. Seq2Seq Models (Encoder-Decoder Architecture)
9. Hybrid Models (e.g., T5)

# Comparison of Key Architectures
| #SNo| #Architecture| #Strengths  | #Weaknesses |#Use Cases |
| :---| :--- | :--- | :--- |:--- |
|1 | N-gram Models  |Simple, easy to implement |Poor long-range dependencies, limited to local context | Autocomplete, simple text generation |
|2 | RNNs  |Sequence modeling, handles variable-length input |Vanishing gradient problem, weak long-range memory | Language modeling, text classification | 
|3 | LSTMs  |Captures long-range dependencies |Slower to train, computationally expensive | Translation, text generation, time series forecasting | 
|4 | GRUs  |Simplified version of LSTM, faster training |Less powerful for complex tasks | Similar to LSTMs, efficient for tasks with shorter sequences |
|5 | Transformers  |Long-range dependencies, parallelizable, scalable |High computational cost | State-of-the-art NLP, large-scale models like GPT, BERT | 
|6 | Seq2Seq (RNN/Transformer)  |Effective for sequence-based tasks |Transformer-based models are preferred over RNNs | Translation, summarization, dialogue systems | 
|7 | Auto-Regressive (GPT)  |Excellent for text generation |Lacks bidirectional context | Text generation, dialogue systems, creative writing | 
|8 | Auto-Encoding (BERT)  |Strong for understanding tasks (e.g., classification) |Not suitable for text generation | Classification, question-answering, named entity recognition | 
|9 | Hybrid Models (T5)  |Unified framework for multiple NLP tasks |Requires large datasets and resources | Translation, summarization, classification, text generation |
